## 2. 高优先级问题（P1）

### P1-1 只给 `auxdir`、不给 `jobname` 时，`run_pipeline` 静默返回空结果

位置：`src/pytexlogs/core/engine.py:86-97`

现象：

```python
aux = ...  # 含 main.log、main.tex
run_pipeline(auxdir=aux, print_terminal=False)
# -> tool_results=0, 没有 main.log 的解析结果
```

根因：

- `jobname is None` 时被固定成 `"pytexlogs_default_job"`；
- 虽然传入的 `auxdir` 被保留，但 `plan_default_steps()` 只找 `${jobname}.log`；
- 结果是计划步骤为 `pdflatex`，发现路径却是 `aux/pytexlogs_default_job.log`，不存在的文件被跳过。

影响：调用方只传目录时得到一份“成功但为空”的报告，比抛错更危险。CLI 目录模式有自己的 jobname 推断，库 API 没有。

建议：

- `jobname` 为空时从 `root_file` 推断；否则扫描 `auxdir` 下的 `*.tex` / `*.log`（与 CLI `_find_tex_in_dir` / `_find_jobname_from_logs` 同规则）；
- 若无法推断，直接抛 `ValueError`，不要静默使用默认 jobname；
- 增加回归：`run_pipeline(auxdir=aux)` 必须解析到 `main.log` 或明确失败。

### P1-2 `captured_outputs` 的键不会参与默认步骤规划

位置：`src/pytexlogs/core/engine.py:95-97`、`src/pytexlogs/core/manager.py:117-121`

现象：

```python
run_pipeline(captured_outputs={"biber": biber_log}, print_terminal=False)
# -> tool_results=0；biber 文本完全没被解析
```

根因：

- `steps=None` 时只调用 `plan_default_steps(jobname, auxdir)`；
- `captured_outputs` 的 key 不在计划步骤里，后续 `iter_steps` 根本不会遍历到该 step；
- `captured_outputs={"pdflatex": ...}` 只是碰巧因为默认计划包含 `pdflatex` 才能工作。

影响：同一份 `captured_outputs` 里，pdflatex 能解析、biber/bibtex/custom step 却被静默丢弃，属于高隐蔽性数据丢失。`parse_auxdir(steps=None, captured_outputs=...)` 同样受影响。

建议：

- `steps = plan_default_steps(...)` 后，把 `captured_outputs` 中尚未出现的 key 追加到步骤列表（保持确定性顺序）；
- 或在 `LogParserManager.iter_steps()` 统一做 union，避免两个入口行为不一致；
- 回归：只给 `captured_outputs={"biber": ...}` 时必须得到 biber 结果。

### P1-3 折行的 `Missing character` 会吞掉紧随其后的普通警告

位置：`src/pytexlogs/parsers/latex.py:508-522`（缓冲分支）、`latex.py:176`（已有 `_ENTRY_START_PATTERNS` 未使用）

现象：

```text
Missing character: There is no 中
LaTeX Warning: Something happened on input line 7.
```

输出只有一条：

```text
warning line=1 text="Missing character: There is no 中LaTeX Warning: Something happened on input line 7."
```

原本的 `LaTeX Warning: Something happened...` 没有再单独成条。

根因：

- 第一行没有以 `!` / `?` 结束，进入 `_missing_char_buffer`；
- 下一行进入 `_missing_char_buffer` 分支后，只检查 `!`、空行、文件栈行；
- 普通 `LaTeX Warning` 不匹配这些条件，被当成续行追加并直接 `return`；
- 该分支在 `latex_warn_re` 之前执行，所以警告解析逻辑没有机会运行。

影响：pdfTeX 的 `Missing character` 在 `max_print_line` 折行时并不保证首行以 `!` 结束；紧跟其后的普通警告会丢失，或被合并成一条语义错误的大文本。

建议：

- 在 `_missing_char_buffer` 分支追加前，先用已有的 `_ENTRY_START_PATTERNS` 判断“新条目开始”；
- 命中新条目时先 `_record_missing_character(...)` 清空缓冲，再继续正常解析当前行；
- 回归：折行 Missing character + 普通 `LaTeX Warning` 必须得到两条独立条目。

### P1-4 裸 `---while reading file` 被重复记录，第二次还带上前一行文本和错误文件

位置：`src/pytexlogs/parsers/bibtex.py:168-173`、`bibtex.py:239-260`

现象：

```text
This is BibTeX, Version 0.99
---while reading file main.aux
```

实际得到两条 error：

```text
main.tex:1  ---while reading file main.aux
main.aux:1  This is BibTeX, Version 0.99
```

根因：

- `_scan_multiline_patterns()` 对 `error_aux_file_re` 的裸行使用 `m.group(0)`，先正确记一条；
- 主循环又调用 `_parse_line_with_unified_error(line, last_line)`；
- 该函数在 `m.start() == 0` 时用 `last_line` 作为 message，于是把上一行 `This is BibTeX...` 当成错误文本；
- `_resolve_aux_file` 把第二次的 file 解析成 `main.aux`，与第一次的 `main.tex` 不同，`_add_entry` 的去重键失效，两条都留下。

影响：真实的 BibTeX 裸 aux 错误会变成两条，第二条的文本和文件都错误；在 JSON/CSV/SARIF 里会污染定位，也可能触发错误的 hint。

建议：

- 裸 `---while reading file` 只由 `_scan_multiline_patterns` 记录；主循环遇到 `m.start()==0` 且 `group(1)` 为空时跳过；
- 或统一两处的 file/text 归一化，让 `_add_entry` 能去重；
- 回归：裸 aux 行必须只产生一条、file 为 `.tex`（或明确约定的 `.aux`）。

## 3. 中优先级问题（P2）

### P2-1 `print_summary(stream=...)` 与无 `rich` 回退会丢掉 `[E]`、`[一般编译]` 等字面标签

位置：`src/pytexlogs/display/printer.py:38-42`（`_FallbackConsole`）、`printer.py:70-75`（`_print_to_stream`）

现象：

- `print_summary([log], stream=StringIO())` 的 stream 内容里没有类别标签 `[一般编译]`，也没有条目级别符号 `[E]`；
- 强行把 `_RICH_CONSOLE` 设为 `_FallbackConsole()` 时，终端输出同样丢标签；
- 返回值 `print_summary` 的 `output_lines` 反而是完整的。

根因：

- `_print_to_stream()` 在 `markup` 非空时用 `_strip_rich_markup(markup)`，而不是调用方已经传入的 `plain`；
- `_FallbackConsole.print()` 也只有 `markup` 一个输入，统一走正则剥标签；
- `[一般编译]` 和 `[E]` 在结构上也是方括号文本，被当成 rich 标签一并删除。

影响：

- 使用 `stream` 参数的重定向/测试/日志采集会丢展示信息；
- `rich` 是可选依赖，未安装时默认终端摘要同样降级；
- CLI 当前使用返回值而不是 stream，所以主 CLI 路径暂时没有暴露，但公共 API 已经失真。

建议：

- `_print_to_stream()` 直接写 `plain`；只有确实需要从 markup 推导时才 strip；
- 给 `_FallbackConsole` 增加 `plain` 输入，或在 `print_summary` 的 fallback 分支直接 `print(plain)`；
- 回归：stream 文本必须包含类别标签和级别符号；无 rich 时同样。

### P2-2 `write_report()` 文档承诺失败返回 `None`，实际会抛异常

位置：`src/pytexlogs/core/report.py:90-118`

现象：

```python
parent_file.write_text("x")
write_report(report, parent_file / "r.json")
# -> FileExistsError
```

`path.parent.mkdir(parents=True, exist_ok=True)` 和 `tempfile.mkstemp(...)` 都在 `try` 之外；只有后面的写入/替换在 `try` 内。

影响：

- `run_pipeline` 外层捕获后能继续，但直接调用公共 `write_report()` 的调用方会拿到异常，而不是文档说的 `None`；
- 报告落盘失败的错误类型不稳定（`FileExistsError`、`PermissionError`、`OSError` 等）。

建议：

- 把 `mkdir`、`mkstemp`、`write`、`replace` 全部纳入 `try`；
- 统一捕获 `OSError`，清理临时文件并返回 `None`；
- 回归：父路径是文件、目录只读、临时文件创建失败三种场景都应返回 `None` 且不留 `.tmp`。

### P2-3 `parse_log_file` 文档声明支持 `.xlg`，但注册表没有该后缀

位置：`src/pytexlogs/easy.py:92`；`src/pytexlogs/core/registry.py:125-203`

现象：

```python
parse_log_file("main.xlg")
# -> tool_name="latex", entries=0
```

一段带 `ERROR: bad index` / `WARNING: weak` / `Output written on main.ind` 的 `.xlg` 文本被当成 LaTeX 日志，只从最后一行误读出了 `pages_output=2`，没有任何错误/警告条目。

根因：

- `_guess_parser_from_path()` 对未知后缀回退 `pdflatex`；
- Xindy 规格只注册了 `.glg/.alg/.slg/.ilg`，没有 `.xlg`；
- 文档却把 `.xlg` 列入支持范围。

影响：按文档使用 `.xlg` 的用户会得到“解析成功但为空”的结果；这是文档/路由契约不一致。

建议：

- 若 `.xlg` 确实是目标格式，把它加入 Xindy 规格并补 fixture；
- 否则从 `parse_log_file` 文档删除 `.xlg`，避免误导；
- 未知日志后缀建议给出 warning，而不是静默回退 LaTeX。

### P2-4 陈旧 `.bcf` 会把 BibTeX 的 `.blg` 强制路由到 Biber

位置：`src/pytexlogs/core/logkind.py:44-58`；`logkind.py:105-110`

现象：

```text
main.blg = "This is BibTeX, Version 0.99d..."
main.bcf = "<bcf:controlfile/>"
sniff_bib_tool(main.blg) -> "biber"
plan_default_steps("main", aux) -> ["pdflatex", "biber"]
manager.run(steps=["biber"]) -> biber, entries=0
```

根因：

- 判定顺序把“同名 `.bcf` 存在”放在 `.blg` 头部特征之前；
- 从 biblatex 切回 BibTeX、或没有清理构建目录时，旧 `.bcf` 很常见；
- Biber parser 读 BibTeX 日志时几乎不会产生条目。

影响：BibTeX 的错误/警告全部丢失，报告显示 biber 成功但 0 条。

建议：

- 先读 `.blg` 头部；头部明确 `This is BibTeX` 时优先 bibtex；
- 若 `.bcf` 与 `.blg` 头部冲突，记录 warning 并按头部走，或要求显式指定 backend；
- 回归：BibTeX 头 + 陈旧 bcf 必须仍然选 bibtex。

### P2-5 CLI `--no-hints` 只影响文本摘要，不影响 JSON/CSV/SARIF

位置：`src/pytexlogs/cli/main.py:318`、`main.py:389-394`、`main.py:428`

现象：

```bash
pytexlogs export main.log --format json --no-hints
# hints 仍然有 1 条
```

根因：

- `show_hints` 只传给了 `print_summary(show_hints=...)`；
- `to_json(filtered_for_output, language=lang)`、`to_csv(...)`、`to_sarif(...)` 都没有传 `include_hints`，使用默认 `True`。

影响：CI/脚本用户以为关闭了提示，导出文件里仍然带 hint；与 `--no-hints` 的全局选项语义不一致。

建议：

- 三个 exporter 都传 `include_hints=show_hints`；
- 回归：`--format json/csv/sarif --no-hints` 的 `hints`/`hint` 必须为空。

### P2-6 英文摘要缺少 `external`、`custom` 类别翻译

位置：`src/pytexlogs/display/formatter.py:34-66`、`formatter.py:98-99`

现象：

```python
print_summary([ParsedLog(category="external", ...)], language="en")
# 类别标签仍是“外部工具”
```

根因：

- `CATEGORY_ORDER` 已扩到 8 类，`CATEGORY_LABEL` 也有 `external/custom`；
- `_BuiltinDictTranslations` 只覆盖了原来的 6 类，没有 `"外部工具"` 和 `"自定义解析"`。

影响：英文输出混入中文类别，i18n 不完整。

建议：补两条映射，并给 8 类都加一个英文断言测试。

### P2-7 `show_log_entries()` 不接受报告对象：`ToolResultReport` 崩溃，`ReportEntry` 静默为空

位置：`src/pytexlogs/display/printer.py:310-318`、`src/pytexlogs/display/formatter.py:187`

现象：

```python
show_log_entries([ToolResultReport(...)])  # AttributeError: 'ToolResultReport' object has no attribute 'level'
show_log_entries([ReportEntry(level="error", ...)])  # 输出为空，不报错
```

根因：

- `show_log_entries` 对非 `ParsedLog` 列表统一包成 `ParsedLog(entries=...)`；
- `_group_by` 只认 `LogLevel` 枚举键，`ToolResultReport` 没有 `.level`，`ReportEntry.level` 是字符串；
- 两条路径分别是“崩溃”和“静默丢弃”。

影响：公共 API 接受 `Any`，但实际只对 `LogEntry` 安全；调用方传报告模型时行为不可预期。

建议：

- 入参只接受 `LogEntry` / `ParsedLog` 时，先做显式类型检查并抛出可读 `TypeError`；
- 若要支持报告模型，统一通过 `level_from_value()` 把 `ReportEntry.level` 归一成 `LogLevel`，并展开 `ToolResultReport.entries`；
- 回归：三种输入（`LogEntry`、`ReportEntry`、`ToolResultReport`）行为明确且不静默。

## 6. 建议修复顺序

1. **P1-1 / P1-2**：先修 `run_pipeline` 的默认规划，避免“成功但空”的报告。建议抽一个 `resolve_steps(jobname, auxdir, captured_outputs, steps)` 统一入口。
