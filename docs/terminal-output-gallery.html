入口与帮助

用户最先看到的框架文案：帮助、版本、demo、explain。

--help 主帮助页

argparse 原生骨架：usage 自动折行、英文标题（positional arguments / options），中文描述混排；无颜色、无分组。

$ pytexlogs --helpSTDOUT
usage: pytexlogs [-h] [--version] [--completion {bash,zsh,fish,powershell}]
                 [--lang {en,zh}] [--format {text,json,csv,sarif}]
                 [--output OUTPUT]
                 [--severity {error,warning,info,all,error+warning}]
                 [--root-file ROOT_FILE] [--jobname JOBNAME] [--open]
                 [--open-all] [--editor EDITOR] [--dry-run]
                 [--max-entries MAX_ENTRIES] [--no-hints]
                 [--baseline BASELINE] [--recursive]
                 <subcmd> ...

PyTeXLogs: LaTeX 工具日志解析 CLI（零第三方硬依赖）。

positional arguments:
  <subcmd>
    check               检查日志，发现 ERROR 则返回 exitcode=1
    summary             仅打印摘要（不返回 error exitcode）
    export              导出 JSON/CSV/SARIF（默认 stdout，--format 覆盖）
    explain             查询某条日志文本对应的可执行建议（hint）
    demo                跑独立库内置演示（integration_demo.run_demo）

options:
  -h, --help            show this help message and exit
  --version             show program's version number and exit
  --completion {bash,zsh,fish,powershell}
                        输出指定 shell 的补全脚本后退出（bash/zsh/fish/powershell）
  --lang {en,zh}        摘要语言（zh / en），默认 zh
  --format {text,json,csv,sarif}
                        输出格式：text/json/csv/sarif（默认 text）
  --output, -o OUTPUT   输出到文件（默认 stdout）
  --severity {error,warning,info,all,error+warning}
                        仅展示/导出 ≥ 该严重度的条目（默认 error+warning）
  --root-file ROOT_FILE
                        传给 parser 的主 .tex 路径（可选）
  --jobname JOBNAME     目录模式的 jobname（默认取目录里首个带 \documentclass 的 .tex）
  --open                尝试对 ERROR 条目打开编辑器跳转（默认只开第一条）
  --open-all            --open 时打开所有 ERROR 条目（默认只开第一条）
  --editor EDITOR       编辑器：auto | code | subl | nvim | gvim | custom:"code
                        --goto %f:%l"
  --dry-run             仅打印 --open 将要执行的命令，不真的启动进程
  --max-entries MAX_ENTRIES
                        文本摘要每个分组最多展示 N 条（默认 10，0 表示不限制）
  --no-hints            不在摘要里追加可执行建议
  --baseline BASELINE   上次的报告 JSON；只输出本次新增/变化的条目
  --recursive           目录模式递归扫描子目录（只处理含 .log/.tex 的目录）

示例：pytexlogs main.log | pytexlogs main.log --open | pytexlogs Build/ --jobname main --format sarif | pytexlogs explain 'Missing character'
退出码：0=无错误；1=check 命中错误（或 --fail-on warning 时命中警告）；2=参数/运行异常。
  • 帮助正文按终端宽度（此处 80 列）二次折行；--severity 的 choices 很长，占满一整行。
  • usage:、positional arguments:、options: 为 argparse 默认英文，与中文简介混排。
  • 退出码说明直接接在示例后，没有独立小节。

explain：命中建议

单条建议正文；若有可执行命令，会另起 $ cmd 行（本次该条无命令）。

$ pytexlogs explain 'Missing character'STDOUT
当前字体不含该字形：更换包含该字符的字体，或用 \newunicodechar 映射；中文/全角字符请配置 ctex/xeCJK 中文字体。
  • 无标题、无缩进层级；正文与命令行的前缀不统一。

explain：无匹配 / 空参数

两条错误提示都走 stderr，纯文本、无颜色、无图标。

$ pytexlogs explain '乱码文本abc' | pytexlogs explainSTDERR
没有匹配到内置建议；可先用 `pytexlogs <log>` 查看条目上下文。
请给出一段日志文本，例如：pytexlogs explain 'Missing character'
  • 与 check 的 warning: 前缀风格不一致（一个是中文句子，一个是英文小写前缀）。

04

异常、空态与边界

空结果、坏输入、解析失败、顶层异常、dry-run。

无解析结果

空项目时唯一一行提示；全角括号，无颜色、无图标。

$ pytexlogs check（空目录）STDERR
（无解析结果。请传入 .log / .blg 或 aux 目录）
  • 没有提示「当前目录没有日志」，也没有下一步命令建议。

基线报告不存在

--baseline 路径不存在时早退，避免抛堆栈。

$ pytexlogs check --baseline missing.jsonSTDERR
基线报告不存在：missing.json（先用 --output 导出一次 JSON 报告）
  • 整句中文 + 英文参数名混排，--output 未加反引号。

传入路径不存在 / 不是文件也不是目录

先打一条小写 warning:，再打「无解析结果」；两行都走 stderr。

$ pytexlogs check not_a_file.texSTDERR
warning: not_a_file.tex 不是文件也不是目录，跳过
（无解析结果。请传入 .log / .blg 或 aux 目录）
  • warning: 是小写英文前缀，和 logging 的 WARNING:、摘要里的 [W] 是三套写法。
  • 跳过输入后仍然继续，最终以「无解析结果」收尾，退出码 0——CI 里会当成成功。
  • 拼错的子命令（pytexlogs nonsense）也会被 _normalize_argv 当成路径走同一条分支，不报 usage。

参数错误：argparse 直接退出

argparse 自己打印子命令 usage + 一行 prog: error: …，退出码 2；不经过任何 PyTeXLogs 样式层。

$ pytexlogs check <log> --severity bogusSTDERR
usage: pytexlogs check [-h] [--lang {en,zh}] [--format {text,json,csv,sarif}]
                       [--output OUTPUT]
                       [--severity {error,warning,info,all,error+warning}]
                       [--root-file ROOT_FILE] [--jobname JOBNAME] [--open]
                       [--open-all] [--editor EDITOR] [--dry-run]
                       [--max-entries MAX_ENTRIES] [--no-hints]
                       [--baseline BASELINE] [--recursive]
                       [--fail-on {error,warning}]
                       [paths ...]
pytexlogs check: error: argument --severity: invalid choice: 'bogus' (choose from 'error', 'warning', 'info', 'all', 'error+warning')
  • 这段 usage 与主帮助页的 usage 不同（子命令版只列本地参数），宽度也按 80 列折行。
  • error: argument --severity: invalid choice 全英文，与中文界面混排。
  • --fail-on 只出现在 check 子命令这边，主 --help 完全不提。

解析失败块（构造示例）

parse_exception 非空时保留结果并追加该块；文案取自 cli/main.py::_MSG，此处为构造数据。

$ pytexlogs check <损坏的项目>STDOUT
=== 解析失败 ===
biber: ValueError: 无法读取 main.bcf（编码不可识别）
latex: OSError: main.log 在第 812 行被截断
存在解析失败，见上方解析失败列表
  • === 解析失败 === 与摘要的 ==== 横幅是又一门「等号语言」，且只有 3 个 =。
  • 失败行 tool: Type: message 无缩进、无颜色。
  • 最后一句「存在解析失败，见上方解析失败列表」重复了标题信息。

顶层异常（构造示例）

logging 先打 ERROR: CLI 异常 + 堆栈，再打一行中文兜底；两段都走 stderr。

$ pytexlogs check <触发异常的输入>STDERR
ERROR: CLI 异常
Traceback (most recent call last):
  File "<venv>\Lib\site-packages\pytexlogs\cli\main.py", line 501, in main
    raise ValueError("demo")
ValueError: demo
pytexlogs 执行失败：ValueError: demo（设置 PYTEXLOGS_DEBUG=1 可查看堆栈）
  • 堆栈前缀 ERROR: 与中文兜底句重复表达同一件事。
  • PYTEXLOGS_DEBUG=1 是环境变量，却没有在帮助页出现。
  • 异常信息里含绝对路径，长路径会整行溢出。

--open --dry-run

摘要之后另起一行 [dry-run open] $ <命令>，走 stderr（此处与 stdout 合并展示）。

$ pytexlogs check <log> --open --dry-runSTDOUT
[dry-run open] $ C:\Applications\Scoop\apps\vscode\current\bin\code.CMD --goto \usr\local\texlive\2024\texmf-dist\tex\latex\base\article.cls:5
  • [dry-run open] 为英文方括号标签，和摘要的 [E] 同级但风格不同。
  • 路径来自日志内容 \usr\local\...，在 Windows 上被原样拼进命令（编辑器跳转的已知边界）。

logger 通道、无 rich、窄终端。

use_logger=True：日志通道输出

每一行都带 LEVELNAME: 前缀；INFO 组因根 logger 默认 WARNING 而不出现。

$ show_log_entries(..., use_logger=True)STDOUT

06

观察与调整方向

以下不是要一次全改，而是把可独立调整的零件列出来，便于挑方向。左边是现状的结构性问题，右边是可选的美化路线。

现状观察（按影响排序）

  • 固定 74 列，不跟终端宽度 —— SUMMARY_TOTAL_LEN = 74（display/formatter.py:81）。60 列会溢出折行，120 列右侧空一大截；摘要头、等级横幅、分类底边全部绑死这个值。
  • 折行没有悬挂缩进 —— rich 在 markup 上直接折行，续行回到第 0 列（80 列日志里 on input line 49. 顶格）。条目、hint、分类标题都受影响。
  • 框架字符四套并存 —— =（等级）、+--/-（分类）、↳（建议）、…（折叠）、[+]/[-]（文献）、(*)（Top 引用）；ASCII 与 Unicode 混排，没有统一语法。
  • 层级只有两级，且框架比内容重 —— 每个等级一条 74 列横幅；每个分类再一条 74 列标题 + 74 列底边。单条 warning 也要 4 行框架。
  • 颜色 8+ 种，dim 组对比度低 —— red/yellow/blue + dim/dim magenta/dim cyan/dim green + #d79921 金 + cyan 箭头；没有图例，也没有 --no-color 开关（只有 rich 识别的 NO_COLOR 环境变量）。
  • 符号与语言不统一 —— [E]/[W]/[I]/[T]/[F]/[G]/[P] 是英文缩写，标题却是中文；=== PyTeXLogs Summary ===、By category:、warning: 在中文模式下照打。
  • 计数与归属缺失 —— 只有 CLI 头 compile=3；分组标题不带条数，等级横幅不带总数；用户要自己数。compile 是内部键，不是显示名。
  • hint 与条目同一平面 —— 6/7 空格缩进、无边框/底色；长建议会顶格折行，并和下一条日志粘连。
  • 错误上下文没有进入摘要 —— LogEntry.error_pos_text（? 上下文 / l.5 \foobar）被模型保存，但 _format_entry 只输出 file:line --> text；importance、stats 同样不进终端。
  • 参考文献面板是独立风格 —— 只用 [+]/[-]、青色 key、固定 40 列 key 宽、(*) 排行；和主日志块没有共享标题/分隔线语言。
  • 异常/空态无样式 —— （无解析结果…）、warning: …、pytexlogs 执行失败：… 全是裸文本；stderr 与 stdout 的视觉完全一样。
  • 帮助页是 argparse 原生英文骨架 —— usage:/positional arguments:/options: 英文，描述中文；80 列折行；无分组、无示例小节、无颜色。
  • 两套渲染路径不一致 —— CLI 走 use_logger=False + 字符串拼接；库默认 use_logger=True，会给每一行加 ERROR:/WARNING: 前缀，且 INFO 组默认被吞。

可选调整方向

  • 宽度自适应 —— 把 SUMMARY_TOTAL_LEN 换成按 Console.width 计算的 min(max(width - 2, 60), 100)；同时给条目/建议加 hanging indent（rich Text + padding，或先按宽度预折行再补缩进）。
  • 统一框架语法 —— 二选一：① 轻量 ASCII：等级用 == 错误 · 3 ==、分类用 -- 一般编译 · 3 --；② box-drawing：╭─ 错误 (3) ─╮ / ├─ 一般编译 / │ [E] … / ╰─。不要再混 +--、====、(*)。
  • 计数上标题 —— 等级横幅带总数（错误 · 3），分类标题带条数（一般编译 · 3），折叠行改为 └─ 其余 346 条（--format json），并放到组末而不是条目流里。
  • 颜色收敛 + 降级 —— 主色只留 red/yellow/blue 三档语义 + 一个 accent；T/F/G/P 合并为同一 muted 色，用 glyph（[T]/[F]）而不是四种 dim 色相区分；补显式 --no-color（内部把 Console.no_color 打开）。
  • hint 面板化 —— 建议改成带左轨的块：│ ↳ …，命令行 │ $ …；长建议可折叠到 --hints=full，默认只留一行。多条命令按「先跑哪条」编号。
  • 文案统一 i18n —— 把 === PyTeXLogs Summary ===、By category:、By parser:、warning:、[dry-run open]、篇 全部搬进 _MSG；中文模式不出现英文骨架，英文模式处理单复数与尾随空格。
  • 统计头重做 —— PyTeXLogs · main.tex · 3 errors / 2 warnings 一行；category 用显示标签（一般编译）并对齐成两列表格，而不是 compile=3。
  • 空态/异常统一 —— 统一前缀（✗ / ! / …）+ 一行原因 + 一行下一步命令；stderr 用颜色时也遵守 NO_COLOR；路径不存在时退出码不要 0。
  • 帮助页 —— argparse 自定义 formatter_class + 中文分组（常用/输出/过滤/编辑器）；示例单独一节；可加 --style/--theme 的说明。
  • 参考文献面板 —— 并入主框架：参考文献 · +12 / -3 / 87；新增/移除用两列 diff；Top 引用用 █ 比例条或右对齐条形，和条目共享缩进。
  • 错误上下文 —— 把 error_pos_text 作为条目的第二行（ ⌐ l.5 \foobar）或折叠子行，至少在 ERROR 上显示；importance 可做分组排序而非丢弃。
