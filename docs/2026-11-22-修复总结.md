## 2. 可靠性与接口修复（P2）

| 编号 | 问题 | 修复结果 |
|---|---|---|
| B5 | Biber 解析器实例复用旧路径缓存；引用统计为 0 | `BiberParser.parse()` 开头清空 `_resolved_paths`，与 BibTeX 对齐；`Found N citekeys` 接线 `total_citations`；同目录 `.bcf` 的 citekey 去重后写入 `unique_citations` |
| B6 | `to_json(ParsedLog)` 不可用/契约不明 | 新增 `ParsedLog` 分支（`results: [parsed_dict]`）、hint 收集、`filter_by_level` 返回新 `ParsedLog` 并重算 stats |

| B8 | Windows 下编辑器命令解析与 `code.cmd` 识别失败 | 自定义命令改用 `shlex_split`；识别 `code.cmd/code.bat`；`_flatten_entries` 支持 `ParsedPipelineReport/ParsedLog/ToolResult/ToolResultReport/LogEntry/list` |
| B9 | registry 元数据与 parser 自报漂移；`category/importance` 注册默认值不读类属性 | 四个 builtin spec 对齐 parser；`register()` 未显式给元数据时从 parser 类属性读取；`.log` 后缀只保留给 LaTeX 系列 |

| B13 | LaTeX 专用告警分支被通用 `latex_warn_re` 提前吃掉，8 个分支不可达 | 专用分支前置；保留句末标点；`(biblatex) main` 续行保留；BadBox 前缀快速判断 |
| B14 | manager 与 engine 的单步执行行为分叉 | `manager.run` 新增 keyword-only `root_file`；parser 异常 warning 后跳过该 step；删除不可达 `spec is None` 分支；`easy.parse_auxdir` 透传 |
| B15 | `state.clear()` 与固定 `.tmp` 报告文件存在并发竞争 | `clear()` 改为锁内单次 `_mutate(..., prune=True)`；报告写入改用 `tempfile.mkstemp` 唯一临时文件 |

### B9 的展示策略

`CATEGORY_ORDER` 现在包含 `external` 与 `custom`，分别展示为“外部工具”“自定义解析”；第三方解析器不再被折叠进“一般编译”。未知 category 仍回退 `compile`。

## 3. 结构收敛与清理

### 3.1 新增共享模块

- `src/pytexlogs/core/stats.py`：统计重算单一事实源。
- `src/pytexlogs/parsers/index_patterns.py`：Makeindex / Glossaries / Nomencl 共用的条目、错误、MiKTeX style error、续行正则。
- `src/pytexlogs/parsers/xindy_patterns.py`：Xindy 正则 + `scan_xindy()` 单次扫描器。`XindyParser` 与 `GlossariesParser._parse_xindy` 现在共用同一扫描结果，不再各写一份逐行匹配；同时补齐 `N entries` 回退计数。
- `src/pytexlogs/core/manager.py`：新增 `StepOutcome` 与 `LogParserManager.iter_steps()`，engine 与 manager 共用同一套“查找 spec → 发现日志 → 读取/解析 → 去重”执行器；engine 只负责报告聚合，manager 只负责 `ToolResult` 转换。
- `src/pytexlogs/parsers/path_utils.py`：解析器共用的相对路径处理。

### 3.2 删除的死代码

- 整个 `core/exceptions.py`（确认无引用后删除）。
- `models._resolve_file_path`、`version.script_name`、`registry.iter_specs`、`formatter._ANSI_RE`。
- BibTeX 的 `multi_line_bibtex_error_re`、`multi_line_macro_bibtex_error_re`、`warnings_processed_re`。
- `latex._TempEntry` 空子类、`_BAD_BOX_PATTERNS` 第三位 `is_output` 与 `_is_output`。
- `glossaries._resolve_style_file` 空转分支、`encoding.FALLBACK_ENCODINGS` 中不可达的 `utf-8`。

### 3.3 其他一致性修复

- `glossaries` 增加 `_pending_style_error`，补齐 MiKTeX style error 的 `--` 续行明细，不再丢行。
- `XindyParser` 修复 `.glg` 类别判断未使用实例 `root_file` 的 bug（此前会误判为 `index`）。
- 所有新增/修改的写文件 `open` 显式 `encoding="utf-8"`：CLI trend、`--edit` 源文件、integration demo、三个 examples。
- `display/printer.py` 的 rich 改为惰性导入；无 rich 时使用模块级预编译的 `_MARKUP_STRIP_RE` fallback。
- `formatter._display_path` 使用 `lru_cache(maxsize=4096)` 按 `(path, cwd)` 缓存。
- `latex._parse_file_stack` 增加“行内无括号直接返回”快路径；`engine` 每个 step 只实例化一次 parser。
- `display/formatter.py` 的等级标题、符号、分隔色、日志通道合并为 `_LEVEL_DISPLAY` 单一元数据；`_group_by` 改为枚举 → 显示名的 O(1) 归组。
- `CATEGORY_ORDER` 增加 `external` / `custom`，第三方解析器有独立摘要分组。
- `BaseLogParser.parse_file()` 在 parse 期间设置 `_source_path_hint`，Biber 可据此找到同目录 `.bcf`，Xindy/Glossaries 也能拿到真实后缀。
- `reftracker.detect_mode()` 结果传给 `extract_current_with_counts(mode)`，避免重复扫描；`save_cache` 一次读取 keys/key_counts，未变化时跳过 `save_cache`。
- `print_summary` 每次调用只取一次 `Path.cwd()`，批量格式化不再为每条 entry 重复做系统调用。
- `run_pipeline` 默认 `summary_max_entries=20`，显式传 `None` 可恢复全量摘要。

## 4. 性能验证

| 场景 | 实测 | 阈值/说明 |
|---|---|---|
| 10 万行 LaTeX 日志解析 | 234.78 ms | < 500 ms |

| 200 → 2000 条规模比 | 6.89 | 门禁通过 |
| 10 万行 + hints 总耗时 | 907.06 ms（parse 341.07 + hint 565.99） | < 2 s |

## 6. 兼容性提示

以下变化会改变调用方可见行为，升级时需注意：

1. `run_pipeline()` 默认 `summary_max_entries=20`；需要完整摘要时显式传 `None`。
2. `to_csv()` 新增 `include_hints=True`；设为 `False` 可得到 0.6.1 之前的载荷形状。
3. `LogParserRegistry.register()` 的 `category/importance` 默认改为 `None`，随后从 parser 类属性取值。
4. `ParsedLog` 的 `ReferencesReport` 删除 `previous_aux_hash/current_aux_hash`；`ReportEntry` 删除 `source` 字段。
5. `pytexlogs.core.exceptions` 模块已删除；如外部曾直接导入，需要改用标准异常或公共 API。
6. `manager.run()` 与 `easy.parse_auxdir()` 新增 keyword-only `root_file`；旧位置参数调用不受影响。
7. `to_json(ParsedLog)` 现在有正式契约，返回 `{"results": [<parsed_dict>]}`。
8. `XindyParser` 的 loading 模块 INFO 文本统一为 `Loading module <name>`，与 Glossaries 分支一致。
9. `CATEGORY_ORDER` 新增 `external`、`custom`；这两类条目不再合并到“一般编译”。
10. `BiberParser.unique_citations` 改为同目录 `.bcf` 的 citekey 去重数；找不到 bcf 时为 0，不再用日志数量冒充去重数。
11. `LogParserManager.iter_steps()` 成为 engine/manager 共用执行入口；`StepOutcome` 区分 `error` 与 `skipped_reason`。
