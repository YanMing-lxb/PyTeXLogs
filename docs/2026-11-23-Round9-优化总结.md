## 2. 行为变化

- `.bcf` 不再是“通用日志后缀”；通过注册表按后缀查找不会再命中 Biber。
  目录流水线仍能发现 `.bcf`：Biber 的 discover hook 在缺 `.blg` 时兜底。
- `parse_log_file("main.bcf")` 仍返回 `tool_name="biber"` 的 `ParsedLog`，
  `entries` 为空，`stats["unique_citations"]` 为去重后的 citekey 数。
- CSV 导出对可疑前缀加 `'`，这是安全修正，不改表头、不改行数、不截断文本。
- `run_pipeline` 报告成功时仍写 `custom_fields["_report_path"]`；
  失败时写 `_report_write_error`，不会抛出。
- plain 摘要行现在形如 `  [E] file:line --> text`，与 rich 终端的等级语义一致。
- 参考文献新增/移除块与 Top 引用块在 stream/fallback 下保留 `[+]` / `[-]` /
  `[参考文献]` / `(*)`，不再只剩裸键。
- `show_log_entries` 对不支持的列表项由隐式 `AttributeError` 改为显式 `TypeError`。

## 4. 仍保留

1. `.bcf` 显式解析仍不产生日志条目，这是设计选择：它是 XML 控制文件，
   `entries` 只承载日志文本；citekey 统计放在 `stats`。
2. `show_log_entries` 目前仍不做输出语言切换之外的格式化扩展；如需 JSON
   行内嵌日志对象，应新增专用展示入口而不是放宽入参。
3. 报告写盘失败原因以 `异常类型: 消息` 字符串写入；未拆分结构化字段。
4. 当前工作区未提交，且包含此前多轮既有改动。
