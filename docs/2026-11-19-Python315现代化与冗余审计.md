## 2. Python 3.15 API / 语法采用矩阵

| 能力 | 本次判断 | 依据 |
| --- | --- | --- |
| PEP 649 / 延迟注解 | 删除冗余 future import | 3.15 已默认延迟求值注解 |
| `Path.walk()` | **采用** | 递归扫描有真实场景；测试覆盖 `--recursive` |
| PEP 758 `except A, B` | **不采用** | 唯一元组处理器带 `as exc`，3.15 仍必须括号 |
| `Path.open` / `Path.replace` | **采用** | 报告/状态文件的路径对象已经存在；异常类型与原子替换语义保持 |
| `Path.info` | **否决** | 缓存快照不能用于新鲜存在性判断；本项目无使用点 |
| `uuid.uuid7` | **不引入** | 没有运行时唯一 ID 场景 |
| `Path.copy` / `Path.move` | **不引入** | 本项目没有复制/搬移业务文件的需求 |
| `hashlib.file_digest` | **不引入** | SARIF 指纹哈希的是内存字符串，不是文件流 |
| `StrEnum` / `typing.Self` / `tomllib` | **无场景** | 现有枚举/返回类型/配置读取不满足“必须替换”的条件 |
| `sys.set_lazy_imports` | **不采用** | 没有启动耗时 baseline，不在无证据时引入 |

## 3. 本轮实际改动

### 3.1 语法与路径现代化

- 删除 6 个模块的 `from __future__ import annotations`：这些模块在 3.15 下不再需要
  该兼容导入；没有改动其他代码。
- `cli/main.py::_iter_project_dirs` 从 `rglob("*") + 过滤` 改为 `Path.walk()`：
  - 在遍历时裁剪 hidden 子目录；
  - 最终仍按 `(是否 root, as_posix())` 排序，保持批量处理顺序确定；
  - 现有递归扫描测试通过。
- `core/report.py`、`core/state.py`：
  - `open(tmp, ...)` → `tmp.open(...)`；
  - `os.replace(tmp, path)` → `tmp.replace(path)`；
  - `os.unlink` 失败清理 → `Path.unlink(missing_ok=True)` + `contextlib.suppress(OSError)`；
  - 保留“临时文件 + 原子替换 + 失败回滚 + 锁清理”的契约。
- `exporters/sarif_exporter.py` 的跨盘 `ValueError` 处理改为
  `contextlib.suppress(ValueError)`；`os.path.relpath` 本身保留，因为
  `Path.relative_to` 的跨盘语义不等价。

### 3.2 冗余与重复实现

- 删除 `exporters/json_exporter.py::_filter_flat`：全库无调用者。
- 删除 `core/models.py` 未使用的 `typing.override` 导入（原行用 `noqa: F401` 隐藏）。
- `cli/args.py::_filter_by_level` 删除自建的 `level_order` 字符串表，统一使用
  `LogLevel.severity`。这同时修复了一个真实语义倒置：
  - 旧表：`typesetting=2`、`info=6`；
  - 0.6.1 枚举：`INFO=2`、`TYPESET=3`；
  - 结果：`--severity info` 曾保留 TYPESET 反而滤掉 INFO。
- `exporters/json_exporter.py::filter_by_level`：
  - 报告分支复用 `_filter_report_result()`，不再复制过滤/计数逻辑；
  - 等级桶改为由 `LogLevel` 动态派生，`font/graphic/page` 不再只计入 `total`。
- `_flatten_to_entries` 的多分支 `append` 改为 `extend` 生成器，输入顺序与
  `(entry, category, tool_name, source_path)` 字段顺序保持不变。
- `display/formatter.py`、`display/printer.py`、`parsers/biber.py` 的同类
  `PERF401` 与 `SIM113` 一并收敛；`printer` 的 `enumerate(start=1)` 保持
  “已显示条数 / 剩余条数”与 `break` 时机不变。

## 4. 扩展静态检查的剩余项

```text
ruff check --config pyproject.toml --select PTH,SIM,PERF,B src tests
src/pytexlogs/parsers/latex.py:651:37: PTH118 `os.path.join()` should be replaced by `Path` with `/` operator
```

保留原因：该处是 `os.path.normpath(os.path.join(...))`，源码注释明确说明它只做
字符串规范化、无系统调用；`Path.resolve()` 在 Windows 上会为每个路径触发
`nt._getfinalpathname`/readlink，真实日志上约 19 ms。这里不能用 PTH118 机械替换，
否则会破坏已记录的性能选择。该项不影响项目正式 `ruff` 配置（未启用 PTH）。
